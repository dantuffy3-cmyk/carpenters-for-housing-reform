# RRC Pilot Operating Model
**Carpenters for Housing Reform Victoria**
Version: 1.0 — Working Draft
Date: July 2026
Status: WORKING DRAFT — Not government policy. Requires government, legal, regulatory and insurer development before implementation.

## 1. Practitioner Application

| Field | Detail |
|---|---|
| Responsible party | - Applicant practitioner.<br>- Pilot administrator. |
| Required input | - Completed pilot application.<br>- Identity and contact details.<br>- Practice history summary. |
| Required evidence | - Proof of Victorian operating history where relevant.<br>- Business or employment evidence.<br>- Signed declarations about suitability and accuracy. |
| Decision | - Accept for screening.<br>- Reject as incomplete.<br>- Request further information. |
| Output | - Application record created.<br>- Applicant notified of next step. |
| Escalation trigger | - False or inconsistent information.<br>- Serious suitability concern requiring review. |
| Audit record | - Date of application.<br>- Documents received.<br>- Initial screening note. |

## 2. Evidence of Experience

| Field | Detail |
|---|---|
| Responsible party | - Applicant practitioner.<br>- Pilot administrator or assessor. |
| Required input | - Project history demonstrating renovation experience.<br>- Referee or client evidence where permitted.<br>- Summary of capability domains. |
| Required evidence | - Portfolio items showing renovation work types.<br>- Records demonstrating progressive discovery or escalation judgement.<br>- Evidence of coordination with builders, engineers or licensed trades. |
| Decision | - Experience evidence sufficient.<br>- Further evidence required.<br>- Not suitable for pilot intake. |
| Output | - Experience assessment note.<br>- File ready for portfolio review. |
| Escalation trigger | - Major gaps in evidence.<br>- Evidence suggesting work outside claimed competence. |
| Audit record | - Evidence checklist.<br>- Assessor comments.<br>- Reasons for any deficiency notice. |

## 3. Portfolio Review

| Field | Detail |
|---|---|
| Responsible party | - Assessment reviewer or review team. |
| Required input | - Applicant portfolio.<br>- Experience assessment note.<br>- Published pilot capability criteria. |
| Required evidence | - Dated photos, scope notes and job records.<br>- Examples of planning, documentation and homeowner communication.<br>- Examples of boundary recognition and specialist escalation. |
| Decision | - Portfolio meets threshold.<br>- Portfolio conditionally acceptable.<br>- Portfolio not acceptable. |
| Output | - Structured review summary.<br>- Recommendation to panel. |
| Escalation trigger | - Portfolio contains unsupported claims.<br>- Safety or conduct concerns emerge from examples provided. |
| Audit record | - Reviewer name.<br>- Review template completed.<br>- Capability observations logged. |

## Operating Model Notes

- **PROPOSED:** This operating model is a draft implementation sequence only. It requires regulatory design, legal review, government decisions and insurer input before any operational use.
- **Timeline assumptions:** The model assumes a staged pilot with admission before project activity, active monitoring during live projects, and a distinct evaluation phase after sufficient project evidence has accumulated. Final timing remains **ASSUMPTION** only.
- **Technology and record-keeping assumptions:** The model assumes a secure project register, digital evidence storage, version-controlled disclosure templates and retrievable audit records. Equivalent systems may be possible, but minimum standards would need to be defined.
- **Escalation timing requirements:** The model assumes escalation occurs promptly when risk, scope or responsibility changes. The preferred sequence is to make the area safe, pause affected work, record the condition, notify the homeowner, obtain the appropriate professional input and revise the scope before continuation.
